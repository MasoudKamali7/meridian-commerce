# Meridian Commerce Power BI Dashboard Pack

Everything needed to understand, rebuild and verify the Meridian Commerce Power BI dashboard (3 pages, built on the Phase 6 PostgreSQL views).

The `.pbix` is not generated by these files; Power BI Desktop is needed to open or rebuild it. Keep your `.pbix` in this folder (suggested name `Meridian_Commerce_Support_Dashboard.pbix`).

## Contents

- `dax/measures.dax` - measures. Section A is what the dashboard uses; Section B is optional; Section C is optional dynamic text.
- `powerquery/postgresql_views.pq` - the Power Query exactly as shipped in the PBIX, plus a parameterized option.
- `sql/powerbi_extracts.sql` - SELECT-only extracts (CSV fallback).
- `docs/layout_spec.md` - the three pages as built, and what was planned but not built.
- `docs/dashboard_build_guide.md` - model, settings, QA checklist.
- `docs/data_dictionary.md` - fields, naming map, caveats, current metrics.
- `docs/validation_report.md` - how the dashboard was reconciled with the SQL, rule engine and tests.
- `sample_current_metrics/*.csv` - latest reported metric snapshots (2026-10-15); the PBIX embedded import still reflects the older 2026-10-13 snapshot until refreshed in Power BI Desktop.

## Source views

- `vw_ticket_analytics` (fact, one row per ticket)
- `vw_classification_metrics`, `vw_rule_decision_metrics`, `vw_response_metrics`, `vw_operational_metrics` (single-row summaries)

## Reporting rules

- Do not describe `exact_category_match_rate_pct` as production accuracy. It is not shown on the dashboard.
- Show AI coverage and sample size next to anything about AI.
- Treat operational metrics as the only substantial historical layer, and as synthetic.
- Do not infer AI improvement, time saved or business impact from this data.
- Do not present the human-review rate as a routing finding: it is mostly a result of 1,400 tickets having no AI classification.
